# Feedback

Organisations adopting open-org-spec — fully or partially — are encouraged to share their experience. Two channels:

- **Quick flag** — email `javier.fdez@gmail.com` with subject `[open-org-spec feedback] <one-line summary>`. Your LLM can draft the message.
- **Considered feedback** — open a pull request using the flow below.

## How to file feedback (PR channel)

1. Copy [`templates/feedback.md`](../templates/feedback.md).
2. Save it under `feedback/<org-slug>/<YYYY-MM-DD>-<short-label>.md`. The `<org-slug>` may be your organisation's name, a fictional label, or `anonymous`.
3. Fill in which components of the standard you're using, which you aren't and why, what worked, what didn't, and any suggestions.
4. Open a pull request.

Short feedback is valued. Detailed feedback is valued more. Anonymous feedback is welcome — what matters is honest signal on where the standard earns its keep and where it creaks.

## How feedback feeds back

Feedback is the primary signal shaping the evolution of the meta-spec. Future versions will cite feedback files when adding, removing, or reshaping requirements. Patterns across multiple feedback entries become the argument for change.
