# Review Optimisations

**Owner:** Javier Fernandez
**Status:** Active
**Type:** Command — interactive companion to the agent-metrics optimisation detection

Reviews pending optimisation suggestions generated by the agent-metrics agent (Step 10), presents each to the manifest owner for a decision, and moves approved suggestions to the adopter-declared approved file.

**This command runs in an interactive context only.** It must not be wired to a schedule or run with `--dangerously-skip-permissions`. Human judgment is required for each suggestion.

## Related

- [`spec.md`](./spec.md) — the scheduled agent-metrics agent that generates the suggestions this command reviews
- [`dashboard.md`](./dashboard.md) — on-demand metrics dashboard; companion read-only command

---

## Pattern

### Step 1 — Spawn subagent

Spawn a subagent to execute the review. This keeps the main session context clean and prevents the review flow from polluting the contributor's working context.

Subagent instruction:

> Read `<adopter-declared suggestions file>`. For each entry where `Status` is `⏳ Pending review`:
> 1. Present the suggestion to the user: what triggered it, which command is affected, the recommended action.
> 2. Ask the user: **approve** (stage for routing) or **dismiss**.
> 3. If approved: move the entry to `<adopter-declared approved file>`, appending if the file exists.
> 4. If dismissed: update the suggestion's status in the suggestions file to `Status: ❌ Dismissed YYYY-MM-DD`.
> 5. If the user asks to defer: leave the entry unchanged and note it in the summary.
>
> After processing all pending entries, return a summary: N approved, N dismissed, N deferred.

### Step 2 — Display summary

Display the subagent's returned summary to the contributor.

### Step 3 — Log invocation

Append one entry to the adopter-declared invocation log:

```
YYYY-MM-DD HH:MM UTC | /review-optimisations | files_read: N | catalogue_assisted: false | outcome: success/fail
```
